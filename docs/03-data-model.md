# 03 — Data Model

_Status: **Implemented in Phase 1** (migration `packages/db/migrations/0000_initial_schema.sql`) · PostgreSQL 17_

Source of truth: [`packages/db/src/schema`](../packages/db/src/schema). Enum values are imported from
[`packages/domain`](../packages/domain/src) so the database and business rules share one vocabulary.

## Conventions

- **Money:** integer cents, CAD only (`payments.currency` is CHECK-constrained to `CAD`). Never floats.
- **Rates:** tax rates are integer **parts per million** (GST 5% = 50 000 ppm, QST 9.975% = 99 750 ppm) —
  basis points cannot represent 9.975%. Promotion percentages are basis points (10 000 = 100%).
- **Time:** `timestamptz`, stored UTC, displayed in `America/Toronto` (Montréal).
- **IDs:** `uuid` (`gen_random_uuid()`) for business tables; Better Auth tables use text ids (UUIDs generated by the app).
- **Bilingual content:** paired `*_fr` / `*_en` columns, both `NOT NULL` for names — parity is enforced, not hoped for.
- **Catalog history:** catalog rows are archived (`archived_at`), never deleted; orders snapshot names and prices.
- **Demo data:** `is_demo` on root entities (users, categories, products, modifier groups, promotions, delivery
  zones, orders, loyalty accounts). Demo rows also have `[DÉMO]/[DEMO]` name prefixes, `demo-` slugs and
  `.invalid` emails. `npm run db:purge-demo` removes them atomically.
- **Columns:** camelCase in TypeScript, snake_case in SQL (Drizzle `casing: "snake_case"`).

## Entities, ownership and key constraints

"Owner" = the only module allowed to write the table. Other modules read through that module's services.

### Identity — owner: `identity` (+ Better Auth)

| Table                       | Purpose                                         | Important constraints                                                                         |
| --------------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `users`                     | Account + **role** (`customer`…`owner`)         | Unique `lower(email)`. Role has `input: false` in Better Auth — never settable by clients.    |
| `sessions`                  | Server-side sessions (HTTP-only cookie token)   | Unique token; cascade on user delete                                                          |
| `accounts`, `verifications` | Better Auth credentials / hashed one-time codes | Codes stored hashed, 10-min expiry, 5 attempts                                                |
| `rate_limits`               | Shared auth rate-limit counters                 | Unique key (DB-backed so limits hold across server instances)                                 |
| `customer_profiles`         | Customer profile (1:1): preferred locale, phone | PK = user id                                                                                  |
| `notification_preferences`  | One row per (user, channel, topic)              | PK (user, channel, topic). `consented_at` set when marketing consent is granted (CASL proof). |

### Catalog — owner: `catalog`

| Table                     | Purpose                                | Important constraints                                                                         |
| ------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------- |
| `categories`              | Menu sections                          | Unique slug                                                                                   |
| `products`                | Sellable item                          | `loyalty_qualifying ⇒ is_drink`; image ⇒ FR **and** EN alt text; owner-supplied allergen note |
| `product_variants`        | Size/format **with the price**         | Price ≥ 0; at most one active default per product (partial unique index)                      |
| `modifier_groups`         | Reusable option groups (milk, syrups…) | `0 ≤ min ≤ max`, `max ≥ 1`; `single` ⇒ `max = 1`                                              |
| `modifier_options`        | Options with signed price delta        | —                                                                                             |
| `product_modifier_groups` | Which groups apply to which product    | PK (product, group)                                                                           |

### Ordering — owner: `ordering`

| Table                 | Purpose                                         | Important constraints                                                                                                                                                                                            |
| --------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `orders`              | Order header, totals, pricing snapshot          | **`total = subtotal − discount − reward + delivery + GST + QST + tip`** (CHECK); all amounts ≥ 0; user **or** guest email; delivery ⇔ zone + address; unique `idempotency_key`; `version` for optimistic locking |
| `order_items`         | Lines with frozen names, prices, modifiers JSON | Quantity > 0; `line_total = unit_price × quantity`                                                                                                                                                               |
| `order_status_events` | Append-only status history (who/when/why)       | —                                                                                                                                                                                                                |

### Payments — owner: `payments`

| Table            | Purpose                     | Important constraints                                                                       |
| ---------------- | --------------------------- | ------------------------------------------------------------------------------------------- |
| `payments`       | Provider payment references | Unique (provider, provider_payment_id); `0 ≤ refunded ≤ amount`; CAD only; **no card data** |
| `payment_events` | Webhook inbox               | **Unique (provider, event_id)** → `INSERT … ON CONFLICT DO NOTHING` = idempotent webhooks   |

### Loyalty — owner: `loyalty`

| Table                  | Purpose                           | Important constraints                                                                                                                    |
| ---------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `loyalty_accounts`     | Cached stamp balance (1 per user) | Balance ≥ 0; `version`                                                                                                                   |
| `loyalty_transactions` | **Append-only stamp ledger**      | Sign rules (earn > 0, reverse/convert < 0); adjust requires a reason; **unique (order_item, kind)** → a line earns/reverses at most once |
| `rewards`              | One row per earned free drink     | Unique source ledger entry                                                                                                               |
| `reward_redemptions`   | Reward applied to an order        | **At most one `reserved`/`committed` redemption per reward** (partial unique index)                                                      |

### Promotions, delivery, audit

| Table            | Owner                                         | Important constraints                                                                |
| ---------------- | --------------------------------------------- | ------------------------------------------------------------------------------------ |
| `promotions`     | promotions                                    | Case-insensitive unique code; value > 0; percent ≤ 100%; `ends_at > starts_at`       |
| `delivery_zones` | delivery                                      | Fees ≥ 0; ≥ 1 postal prefix (FSA). Delivery is enabled only if an active zone exists |
| `audit_events`   | every module (append-only, via `recordAudit`) | Never stores secrets/payment data; IPs hashed                                        |

Deliberately **not** in Phase 1 (added with their phases, to avoid speculative schema): refunds table,
promotion redemptions, gift cards, referrals, inventory, store hours/closures, tax-rate table, outbox,
push subscriptions, privacy-request tracking.

## Relationships

```
users 1─1 customer_profiles      users 1─* notification_preferences      users 1─* sessions/accounts
users 1─1 loyalty_accounts 1─* loyalty_transactions 1─0..1 rewards 1─* reward_redemptions *─1 orders
categories 1─* products 1─* product_variants         products *─* modifier_groups 1─* modifier_options
users 0..1─* orders 1─* order_items                  orders 1─* order_status_events
orders 1─* payments                                  payment_events (inbox, keyed by provider event id)
orders *─0..1 promotions                             orders *─0..1 delivery_zones
```

## Transaction boundaries

Each row is one database transaction. Services own the transaction; route handlers never open one.

| Operation                          | Phase | Inside one transaction                                                                   | Concurrency control                                        |
| ---------------------------------- | ----- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Account provisioning (first login) | 1 ✔   | profile + default preferences + loyalty account                                          | `ON CONFLICT DO NOTHING` (idempotent)                      |
| Update account settings            | 1 ✔   | name, locale, preferences, consent timestamp, **audit event** for consent change         | `SELECT … FOR UPDATE` on the marketing preference row      |
| Purge demo data                    | 1 ✔   | all demo rows across modules                                                             | all-or-nothing                                             |
| Place order                        | 6     | order + items + pricing snapshot + slot reservation + reward reservation                 | unique idempotency key; slot capacity counted under lock   |
| Confirm payment (webhook)          | 6     | inbox insert → payment status → order `paid` + status event → loyalty earn → outbox rows | unique event id; order `version`; account row `FOR UPDATE` |
| Staff status transition            | 7     | order status + status event (+ audit for cancel/refund)                                  | `UPDATE … WHERE version = $expected` → 409 on conflict     |
| Earn / convert stamps              | 8     | ledger entries + balance cache + reward rows                                             | account row `FOR UPDATE`; unique (order_item, kind)        |
| Redeem reward                      | 8     | redemption `reserved` → `committed` with payment, or `released` on expiry/cancel         | partial unique index on active redemption                  |
| Refund                             | 6/8   | refund record + payment refunded amount + loyalty reversal + audit                       | payment row `FOR UPDATE`                                   |
